「このAPI、障害が起きたらどうなるんですか？」

以前、非エンジニアのメンバーからそう聞かれたことがある。「フォールバックが効くので、完全に止まることはないですよ」と答えたら、「フォールバックって何ですか」と返された。説明しようとして気づいた。自分がこの言葉を感覚で使っていて、正確な定義を言葉にできていなかったのだ。

この手の言葉は分野をまたいで無数にある。ネットワーク設計の会話でも、Gitの運用でも、AIツールの設定でも、同じように「知っている前提」で飛び交う用語がある。

そこでこのページでは、このブログで扱ってきた用語を1つの表にまとめることにした。読み物ではなく、手元に置いて引くための索引として使ってほしい。分類で絞り込めるように並べてあり、詳しく書いた記事があるものはリンクを張ってある。新しい記事を書くたびに随時追加していく。

なおHTTPステータスコードの定義は MDN Web Docs を参照した。

可用性フォールバック障害やエラー、想定外の状況のときに、完全な停止を避けて代替の手段へ切り替え、限定的ながら処理を継続させる仕組み。例＝外部APIがタイムアウトしたらキャッシュを返す—
可用性フェイルオーバー稼働中のシステムに障害が発生した際、待機系へ切り替えること。自動の場合も手動の場合もある。主にサーバー単位の話—
可用性冗長化サーバーや通信経路を複数用意し、一部が壊れても全体として機能を維持できるようにする設計。フェイルオーバーの前提になる構成—
可用性可用性サービスが止まらずに使い続けられる度合い。「99.9%」のように稼働率で表す—
プロトコルHTTPWebブラウザとWebサーバーがやり取りするための取り決め。「このページをください」「どうぞ」という要求と応答の形を定めている。通信内容は暗号化されない—
プロトコルHTTPSHTTPの通信をTLSで暗号化したもの。盗聴・改ざん・なりすましを防ぐ。ブラウザの鍵マークはこれが有効な印—
プロトコルTLS通信を暗号化する仕組み。かつてのSSLの後継だが、今も「SSL証明書」と通称される—
プロトコルTCPデータを確実に届けることを優先する通信方式。届かなければ再送し、順番も保証する。Webやメールはこちら—
プロトコルUDP確実性より速さを優先する通信方式。欠けても再送しない。動画配信やオンラインゲームで使う—
プロトコルポート番号1台の機器の中で、どのサービス宛の通信かを区別する番号。HTTPは80番、HTTPSは443番が標準。住所に対する部屋番号にあたる—
HTTPステータス1xx（情報）リクエストを受け取り、処理を継続中であることを示す区分—
HTTPステータス2xx（成功）リクエストが正常に完了したことを示す区分—
HTTPステータス3xx（リダイレクト）目的地が別にあり、追加の処理が必要なことを示す区分—
HTTPステータス4xx（クライアントエラー）要求した側に問題がある区分—
HTTPステータス5xx（サーバーエラー）応答する側に問題がある区分—
HTTPステータス200 OK成功。レスポンスの中身にリソースが入っている—
HTTPステータス201 Created成功し、新しいリソースが作成された—
HTTPステータス204 No Content成功したが、返す中身がない—
HTTPステータス301 Moved Permanently恒久的に別のURLへ移動した—
HTTPステータス302 Found一時的に別のURLへ移動している—
HTTPステータス304 Not Modified変更がないので、手元のキャッシュを使ってよい—
HTTPステータス400 Bad Requestリクエストの形式が不正—
HTTPステータス401 Unauthorized認証が必要。「あなたが誰か分からない」状態—
HTTPステータス403 Forbidden認証済みだが権限がない。「誰かは分かったが許可していない」状態—
HTTPステータス404 Not Found指定されたリソースが存在しないGA4「経路探索」分析ガイド
HTTPステータス405 Method Not Allowedそのリソースに対して使えないメソッドだった—
HTTPステータス408 Request Timeoutクライアントが応答せず接続が切れた—
HTTPステータス409 Conflictサーバーの現在の状態と矛盾する要求—
HTTPステータス429 Too Many Requests短時間に送りすぎた（レート制限）—
HTTPステータス500 Internal Server Errorサーバー側で原因不明のエラーが起きた—
HTTPステータス502 Bad Gateway中継サーバーが、その先から不正な応答を受け取った—
HTTPステータス503 Service Unavailableメンテナンス中または過負荷で応答できない—
HTTPステータス504 Gateway Timeout中継サーバーが、その先からの応答を待ちきれなかった—
ネットワークサブネット大きなネットワークを用途や部門ごとに区切った小さなネットワーク。設計を誤ると後からの変更が極めて困難になるサブネット設計パターン集
ネットワークプライベートIPアドレスインターネットに直接出ない、組織内部でのみ使うIPアドレス。設計時の重複が後の統合を阻むIPアドレス設計のベストプラクティス
ネットワークVPC Peering2つの仮想ネットワーク同士を直接つなぐ方式。経路は単純だが接続数が増えると管理が複雑になるVPC間接続方式の完全ガイド
ネットワークプロキシクライアントとサーバーの間に立って通信を中継するサーバー。アクセス制御やキャッシュに使う同上
ネットワークService Meshマイクロサービス間の通信を、アプリ本体のコードから切り離して制御する仕組み。暗号化・リトライ・可視化を担うマイクロサービス時代のネットワーク設計
インフラコンテナアプリと実行環境をひとまとめにして持ち運べるようにした仕組み。同じものがどの環境でも同じように動くDocker最適化・運用ガイド
インフラMPM（event）Apacheがリクエストをどう捌くかの方式。現在の標準はeventで、「Apacheは1リクエスト1プロセス」は旧方式（prefork）の説明Apacheよりnginxが速いは今も正しいのか
ドメインレジストリ「.com」「.jp」といったドメインの種類ごとに、登録情報の大元を管理している組織独自ドメイン割り当て手順とDNSの基礎
ドメインレジストラ利用者がドメインを買う窓口となる事業者同上
ドメインネームサーバー（NS）そのドメインがどのサーバーに対応するかを答える担当サーバー。設定を誤るとサイトが表示されない同上
開発トランクベース開発ブランチを長期間分けず、mainへ小さな変更を頻繁に統合していく開発スタイル。マージ時の衝突を減らせるGitHub Flow vs. トランクベース開発
開発GitHub Flow機能ごとにブランチを切り、プルリクエストでレビューしてからmainへマージする方式同上
開発サブモジュールあるGitリポジトリの中に別のリポジトリを部品として組み込む仕組み。参照先の公開範囲を誤るとソースコードが漏れるサブモジュール経由のソースコード漏えい
開発コピーレフトオープンソースライセンスの性質の一つ。改変・再配布の際、改変部分も同じライセンスで公開することを求める（GPL等）OSSライセンスの基礎知識
セキュリティゼロトラスト「社内だから安全」という境界防御の前提を捨て、内外を問わず全アクセスを都度検証する考え方GCPネットワークセキュリティ設計ガイド
セキュリティ多層防御単一の手段に頼らず、入口・経路・データなど複数の層で守る設計。1つ破られても次が残る同上
セキュリティVPC Service ControlsGoogle Cloudで、特定のサービス境界の外へデータが出ないよう制限する機能VPC Service Controls移行時のトラブルシューティング
データ・AIdbt（Data Build Tool）データ基盤の中で、SQLを使ってデータの変換処理を管理・テストするツールdbt基本機能

データ・AIエージェント人の指示を受け、複数の手順を自分で判断しながら実行するAI。単発の質問応答と区別されるAIエージェントに文脈をどう渡すか

まとめ

用語は単体で覚えるより、分類の中でどこに位置するかを掴むほうが頭に残りやすい。この表も分類列で絞り込めるように並べてある。

混同しやすいものを3つだけ挙げておく。401と403は「誰か分からない」と「誰かは分かったが許可しない」の違い。502・504は500と違って中継サーバーが原因を報告しているため、ロードバランサを挟んだ構成では切り分けの出発点になる。フォールバックと冗長化は、前者が機能レベルの代替で冗長構成を必ずしも必要としない点が異なる。
